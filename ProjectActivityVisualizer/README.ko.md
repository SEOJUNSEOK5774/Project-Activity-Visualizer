# Project Activity Visualizer

[English](README.md) | [日本語](README.ja.md) | [한국어](README.ko.md)

**대상 버전:** 0.1.0  
**배포 상태:** 아래 항목의 패키지 기본 동작 검증 통과 · 배포 준비 중

에셋 저장 이벤트를 기록하고 활동 통계, Contributor 별칭, 패키지 참조 관계, Git 이력을 하나의 대시보드에서 확인하는 언리얼 에디터 플러그인입니다.

## 환경

- 패키지 기본 동작 검증 환경: Windows 64비트 / Unreal Engine 5.8.4.
- 에디터 전용 C++ 플러그인입니다.
- 엔진에 포함된 SQLiteCore 플러그인에 의존하며, 의존성은 플러그인 설명 파일에 선언되어 있습니다.
- Git 기능에는 Git 설치, 로컬 저장소, 언리얼 에디터의 Git Provider 연결이 필요합니다.
- 다른 엔진 버전과 운영체제는 검증하지 않았습니다.

## 패키지 검증 결과 (2026-11-10)

빌드된 Win64 Editor 패키지를 별도의 블루프린트 프로젝트에 설치했습니다. 수동 테스트와 확인 가능한 빌드·에디터 로그 검토를 통해 다음 항목을 확인했습니다.

| 검증 항목 | 확인 결과 |
| --- | --- |
| Win64 Editor 패키징 | BuildPlugin 정상 완료 |
| 새 프로젝트에 설치 | 플러그인 로드 및 독립된 활동 DB 생성 |
| 저장 수집과 통계 | 테스트 에셋 저장이 Raw saves와 UTC 5분 활동 구간으로 표시됨 |
| JSON 내보내기·가져오기 | 내보낸 활동을 새 DB에 복원함 |
| 같은 JSON 재가져오기 | 기존 이벤트 ID를 건너뛰며 중복 기록을 추가하지 않음 |
| 프로젝트 이름 검사 | 프로젝트 이름이 다른 JSON을 거부하며 기록을 추가하지 않음 |
| Git 이력 | 에셋 커밋 2개와 작성자·메시지가 표시되고, 커밋 후 추적 중·미수정 상태를 확인함 |
| 재시작 후 캐시 복원 | 커밋 2개가 CACHED RESULT로 복원되며 기존 조회 시각을 유지함 |
| Git Provider 비활성화·재연결 | 비활성화 중에도 캐시 이력을 유지하고, 재연결 후 갱신하면 로컬 복사본을 업데이트함 |

위 항목은 기본 동작 검증이며 모든 기능에 대한 전체 회귀 테스트는 아닙니다. 팀 자동 가져오기와 전체 Hotspot 조건 조합은 이번 패키지 검증에 포함하지 않았습니다. 아래 소스 컨트롤 로그 문제는 해결되지 않은 상태입니다.

## 설치

1. 언리얼 에디터를 종료합니다.
2. ProjectActivityVisualizer 폴더를 프로젝트의 Plugins 폴더에 복사합니다.
3. C++ 프로젝트는 필요하면 프로젝트 파일을 재생성하고 Development Editor / Win64 대상으로 빌드합니다. 소스 빌드에는 사용하는 언리얼 엔진과 호환되는 C++ 빌드 환경이 필요합니다.
4. Edit > Plugins에서 플러그인을 활성화하고, 안내가 나오면 에디터를 재시작합니다.
5. Window > ProjectActivityVisualizer를 엽니다.

~~~text
YourProject/
└─ Plugins/
   └─ ProjectActivityVisualizer/
      ├─ ProjectActivityVisualizer.uplugin
      ├─ Source/
      ├─ Resources/
      └─ Config/
~~~

빌드된 바이너리를 설치할 때는 엔진과 호환되는 패키지를 사용합니다.

## 처음 사용할 때

1. Editor Preferences > Plugins > Project Activity에서 Contributor Alias를 설정합니다.
2. Project Settings > Plugins > Project Activity에서 수집 여부, Tracked Paths, Ignored Paths, 카테고리 규칙, Hotspot 기준을 확인합니다. 제외 경로가 추적 경로보다 우선합니다.
3. 추적 대상인 /Game/ 폴더의 에셋을 수정하고 저장합니다.
4. 대시보드를 열고 Refresh를 누릅니다.

별칭 변경은 새 기록에 적용되며 기존 기록의 이름을 바꾸지 않습니다. 수집을 꺼도 기존에 저장된 기록은 계속 조회할 수 있습니다.

## 대시보드

| 탭 | 내용 |
| --- | --- |
| Activity | 날짜별 활동, 카테고리, 활동 상위 패키지 |
| Collaboration / Hotspot | 여러 별칭이 기록된 패키지와 선정 이유가 표시되는 검토 후보 |
| Commit history | 선택한 에셋의 소스 컨트롤 상태와 최근 이력 최대 5개 |

Activity 탭의 패키지 행에서 Show History를 누르면 해당 에셋을 조회하고 Commit history 탭으로 이동합니다.

### 기간 선택

- All time: 전체 기간
- Last 24 hours: 최근 24시간
- Last 7 days: 최근 168시간
- Last 30 days: 최근 720시간

필터 기간의 종료 시점은 마지막 대시보드 갱신 시각이며 UTC로 계산합니다. 활동 기록 수, 카테고리 통계, 패키지 순위, 별칭 통계, Hotspot 조건에서 사용하는 활동 근거에 적용됩니다.

일별 그래프는 항상 최근 7개 UTC 날짜를 표시하며, 오늘은 갱신 시점까지의 데이터만 포함합니다. 참조 관계는 현재 저장된 패키지 정보를 사용합니다. 선택한 에셋의 이력에는 활동 기간 필터가 적용되지 않습니다.

## 지표의 의미

- **Raw saves:** 기록된 에셋 저장 이벤트 수입니다. 에디터 자동 저장, 쿠킹, 프로시저럴 저장은 수집 대상에서 제외합니다.
- **Activity buckets:** 동일 패키지·동일 별칭의 저장을 고정된 UTC 5분 구간으로 묶습니다. 같은 구간의 반복 저장은 활동 구간 하나로 계산하며 원본 이벤트는 유지합니다.
- **Named aliases:** 비어 있지 않은 기록상 별칭의 종류 수입니다. 실제 사람 수나 동시 편집자 수를 확정하지 않습니다. 빈 별칭은 상세 창에서 (Unspecified)로 표시합니다.
- **참조 관계:** /Game/ 아래의 직접적인 패키지 참조를 세며 중복과 자기 참조를 제외합니다. 간접 의존성을 재귀적으로 센 값은 아닙니다.
- **Hotspot 후보:** 선택한 기간의 활동 상위 10개 패키지 중 설정한 검토 조건에 맞는 항목입니다. 기본 조건은 활동 구간 3개 이상이면서, 이름 있는 별칭 2개 이상 또는 현재 /Game/ 참조자 1개 이상입니다. 검토용 지표이며 품질이나 생산성 점수가 아닙니다.
- **Unknown:** 해당 근거를 조회하지 못한 상태이며 0개를 의미하지 않습니다. 이동하거나 삭제된 패키지의 과거 경로 기록이 남아 있을 수 있습니다.
- **CACHED RESULT:** 이전 조회 결과입니다. 조회 당시 저장소·브랜치·조회 시각을 표시하며 현재 작업 환경의 상태와 다를 수 있습니다.

저장 횟수와 활동 구간 수는 실제 작업 시간이나 생산성을 나타내지 않습니다. Git 작성자 이름과 Contributor Alias는 별개의 정보입니다.

## 로컬 데이터

프로젝트의 다음 위치에 SQLite DB를 생성합니다.

~~~text
Saved/ProjectActivity/activity.db
~~~

활동 이벤트와 패키지별 마지막 소스 컨트롤 조회 결과를 저장합니다. 새 조회가 성공하면 해당 패키지의 캐시를 갱신합니다. 캐시를 읽기만 할 때는 조회 시각을 변경하지 않습니다.

Export all JSON은 화면에서 선택한 기간과 관계없이 저장된 전체 활동 이벤트를 내보냅니다. 활동 JSON에는 소스 컨트롤 조회 캐시가 포함되지 않습니다.

## 팀 JSON 교환

1. Editor Preferences > Plugins > Project Activity의 Team Exchange Folder에 실제로 존재하는 폴더의 절대 경로를 설정합니다.
2. Export to team folder로 해당 폴더에 활동 JSON을 내보냅니다.
3. Import JSON으로 가져오거나, Enable Automatic Import를 켜서 5초마다 폴더를 확인합니다.

가져오는 활동 데이터의 프로젝트 이름은 현재 프로젝트 이름과 일치해야 합니다. 기존 이벤트 ID는 건너뛰어 같은 이벤트를 중복으로 가져오지 않습니다.

프로젝트를 이동하거나 PC를 바꾼 뒤에는 교환 폴더 경로를 확인합니다. 자동 가져오기는 기본적으로 꺼져 있습니다. 사용하지 않을 때는 끄고, 로컬 교환용 JSON 파일은 배포 패키지에서 제외합니다.

## 알려진 문제

### Git 소스 컨트롤 로그: Invalid path '/Temp'

테스트 프로젝트를 재시작한 뒤 다음 오류가 기록됐습니다.

~~~text
SourceControl: Error: fatal: Invalid path '/Temp': No such file or directory
~~~

Git Provider를 켜 둔 상태에서 Project Activity Visualizer를 비활성화해도 같은 오류가 재현됐습니다. 따라서 이 플러그인 없이도 발생하는 문제입니다. 에디터·Git Provider·프로젝트 설정 중 구체적인 발생 원인은 아직 분리하지 못했으며, 해결 방법도 확인하지 않았습니다.

같은 테스트 환경에서 위 Git 이력 조회와 캐시 검증은 통과했습니다. 이번 버전에서는 이 오류를 알려진 문제로 기록하며 해결됐다고 표시하지 않습니다.

## 현재 구현 범위

활동은 에셋을 저장한 시점에 기록합니다. 저장하지 않은 편집 시간과 에디터를 켜 둔 유휴 시간은 추적하지 않습니다. 실시간 웹 대시보드와 편집 감지는 후속 개발 범위입니다.
