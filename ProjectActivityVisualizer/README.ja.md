# Project Activity Visualizer

[English](README.md) | [日本語](README.ja.md) | [한국어](README.ko.md)

**対象バージョン：** 0.1.0  
**リリース状況：** 下記のパッケージ基本動作検証に合格・配布準備中

アセットの保存イベントを記録し、活動統計、コントリビューターの別名、パッケージの参照関係、Git 履歴を一つのダッシュボードで確認できる Unreal Editor 用プラグインです。

## 動作環境

- パッケージ基本動作の検証環境：Windows 64 ビット / Unreal Engine 5.8.4。
- エディター専用の C++ プラグインです。
- エンジン付属の SQLiteCore プラグインに依存し、依存関係はプラグイン記述ファイルに宣言されています。
- Git 機能には、Git のインストール、ローカルリポジトリ、Unreal Editor での Git Provider の接続が必要です。
- その他のエンジンバージョンおよび OS は未検証です。

## パッケージの検証結果（2026-11-10）

ビルド済みの Win64 Editor パッケージを別のブループリントプロジェクトへインストールしました。手動テストと確認可能なビルド・エディターログの確認により、次の項目が正常に動作することを確認しました。

| 検証項目 | 確認結果 |
| --- | --- |
| Win64 Editor パッケージの作成 | BuildPlugin が正常終了 |
| 新規プロジェクトへのインストール | プラグインの読み込みと独立した活動 DB の作成を確認 |
| 保存の収集と統計 | テストアセットの保存を Raw saves と UTC の 5 分活動区間として表示 |
| JSON の出力・取り込み | 出力した活動を新しい DB に復元 |
| 同じ JSON の再取り込み | 既存のイベント ID をスキップし、重複した記録を追加しないことを確認 |
| プロジェクト名の検査 | 異なるプロジェクト名の JSON を拒否し、記録を追加しないことを確認 |
| Git 履歴 | アセットのコミット 2 件、作成者、メッセージを表示し、コミット後の追跡済み・未変更状態を確認 |
| 再起動後のキャッシュ復元 | 履歴 2 件を CACHED RESULT として復元し、元の取得時刻を保持 |
| Git Provider の無効化・再接続 | 無効時にもキャッシュ履歴を保持し、再接続後の更新でローカルコピーを更新 |

上記は基本動作の検証であり、すべての機能を対象とした回帰テストではありません。チームの自動取り込みと Hotspot 条件の全組み合わせは今回のパッケージ検証に含めていません。以下のソースコントロールのログ問題は未解決です。

## インストール

1. Unreal Editor を終了します。
2. ProjectActivityVisualizer フォルダーをプロジェクトの Plugins フォルダーへコピーします。
3. C++ プロジェクトでは、必要に応じてプロジェクトファイルを再生成し、Development Editor / Win64 ターゲットをビルドします。ソースからのビルドには、使用する Unreal Engine に対応した C++ ビルド環境が必要です。
4. Edit > Plugins でプラグインを有効にし、求められた場合はエディターを再起動します。
5. Window > ProjectActivityVisualizer を開きます。

~~~text
YourProject/
└─ Plugins/
   └─ ProjectActivityVisualizer/
      ├─ ProjectActivityVisualizer.uplugin
      ├─ Source/
      ├─ Resources/
      └─ Config/
~~~

ビルド済みバイナリを使用する場合は、エンジンと互換性のあるパッケージを選んでください。

## はじめに

1. Editor Preferences > Plugins > Project Activity で Contributor Alias を設定します。
2. Project Settings > Plugins > Project Activity で、収集の有効・無効、Tracked Paths、Ignored Paths、カテゴリー規則、Hotspot のしきい値を確認します。除外パスは追跡パスより優先されます。
3. 追跡対象の /Game/ フォルダーにあるアセットを変更して保存します。
4. ダッシュボードを開き、Refresh をクリックします。

別名の変更は新しい記録に適用され、既存の記録は書き換えられません。収集を無効にしても、保存済みの記録は引き続き参照できます。

## ダッシュボード

| タブ | 内容 |
| --- | --- |
| Activity | 日別の活動、カテゴリー、活動の多いパッケージ |
| Collaboration / Hotspot | 複数の別名が記録されたパッケージ、および条件に該当した理由付きの確認候補 |
| Commit history | 選択したアセットのソースコントロール状態と最大 5 件の最近の履歴 |

Activity タブのパッケージ行にある Show History をクリックすると、履歴を取得して Commit history タブを開きます。

### 期間の選択

- All time：全期間
- Last 24 hours：直近 24 時間
- Last 7 days：直近 168 時間
- Last 30 days：直近 720 時間

絞り込み期間は最後にダッシュボードを更新した時刻を終点とし、UTC で計算します。活動件数、カテゴリー統計、パッケージ順位、別名の統計、Hotspot 条件で使用する活動データに適用されます。

日別グラフは常に直近 7 日分の UTC 日付を表示し、当日は更新時点までのデータを含みます。参照関係は現在保存されているパッケージの情報を使用します。選択したアセットの履歴には、活動期間のフィルターは適用されません。

## 指標の意味

- **Raw saves：** 記録されたアセット保存イベント数です。エディターの自動保存、クッキング、プロシージャル保存は収集対象から除外します。
- **Activity buckets：** 同じパッケージ・同じ別名について、固定された UTC の 5 分間隔内で行われた保存を一つの活動区間にまとめます。元の保存イベントは保持します。
- **Named aliases：** 空でない記録上の別名の種類数です。実際の人数や同時編集者数を確定するものではありません。空の別名は詳細画面で (Unspecified) と表示します。
- **参照関係：** /Game/ 内の直接的なパッケージ参照を数え、重複と自己参照を除外します。間接的な依存先を再帰的に数えた値ではありません。
- **Hotspot 候補：** 選択期間の活動上位 10 パッケージのうち、設定可能な確認条件に該当するものです。初期条件は「活動区間が 3 以上、かつ、名前付き別名が 2 以上または現在の /Game/ 参照元が 1 以上」です。確認のための指標であり、品質や生産性の点数ではありません。
- **Unknown：** 必要な情報を取得できなかった状態です。0 件を意味しません。移動・削除前のパッケージパスについて、過去の記録が残る場合があります。
- **CACHED RESULT：** 過去の取得結果です。取得時のリポジトリ、ブランチ、取得時刻を表示します。現在の作業環境の状態とは異なる場合があります。

保存回数と活動区間数は、実作業時間や生産性を表しません。Git の作成者名と Contributor Alias は別の情報です。

## ローカルデータ

プロジェクト内の次の場所に SQLite データベースを作成します。

~~~text
Saved/ProjectActivity/activity.db
~~~

活動イベントと、パッケージごとの最後のソースコントロール取得結果を保存します。新しい取得が成功すると、そのパッケージのキャッシュを更新します。キャッシュを読み出しても、取得時刻は変更しません。

Export all JSON は、画面で選択した期間にかかわらず、保存済みの全活動イベントを出力します。活動 JSON にソースコントロールの取得キャッシュは含みません。

## チームでの JSON 交換

1. Editor Preferences > Plugins > Project Activity の Team Exchange Folder に、実在するフォルダーの絶対パスを設定します。
2. Export to team folder で、そのフォルダーへ活動 JSON を出力します。
3. Import JSON で読み込むか、Enable Automatic Import を有効にして 5 秒ごとにフォルダーを確認します。

読み込む活動データのプロジェクト名は、現在のプロジェクト名と一致する必要があります。既存のイベント ID はスキップし、同じイベントの重複取り込みを防ぎます。

プロジェクトの移動や PC の変更後は、交換フォルダーのパスを確認してください。自動取り込みは初期状態で無効です。使用しない場合は無効のままにし、ローカルの交換用 JSON は配布パッケージから除外してください。

## 既知の問題

### Git ソースコントロールのログ：Invalid path '/Temp'

テストプロジェクトの再起動後、次のエラーが記録されました。

~~~text
SourceControl: Error: fatal: Invalid path '/Temp': No such file or directory
~~~

Git Provider を有効にしたまま Project Activity Visualizer を無効にしても、同じエラーが再現しました。したがって、このプラグインがなくても再現する問題です。エディター、Git Provider、プロジェクト設定のどこに原因があるかは特定できておらず、解決方法も確認していません。

同じテスト環境で、上記の Git 履歴取得とキャッシュの検証は合格しました。このバージョンでは既知の問題として記録し、解決済みとはしていません。

## 現在の実装範囲

活動はアセットを保存した時点で記録します。未保存の編集時間や、エディターを開いたまま操作していない時間は追跡しません。リアルタイム Web ダッシュボードと編集検知は、今後の開発対象です。
